Trabalhos

Filtro por categoria + 3 cards de projeto.

Problema observado
O critique classificou esta como a seção com o pior "veredito de especificidade": categorias de filtro (Branding/UI-UX/Editorial), CTAs ("Ver estudo de caso", "Ver protótipo") e os 3 projetos descreviam uma designer gráfica. Além disso, todos os links de projeto eram href="#" — cliques silenciosos sem destino, um P1 do critique.
Hipótese de melhoria
Reescrever categorias/CTAs/projetos para a realidade de front-end (sem inventar métricas ou clientes) e marcar claramente o que é real (este portfólio) vs. exemplo (2 projetos fictícios) resolve tanto a especificidade quanto a honestidade exigida pelo PRODUCT.md.
Comando escolhido
clarify: a mudança é fundamentalmente de linguagem/rotulagem (o que cada card diz sobre si mesmo), não de estrutura.
Prompt/orientação complementar
"As categorias e os 3 projetos descrevem uma designer gráfica, não a Rayara dev. Reescreva para front-end/JS/CSS. Marque claramente cada card como 'Projeto real' ou 'Projeto de exemplo' — nunca apresente os 2 fictícios como entregas reais — e não deixe link nenhum ir para lugar nenhum: o real aponta pro GitHub verdadeiro, os de exemplo ficam desabilitados com 'Em breve' em vez de href='#' clicável."

Objetivo

Substituir as 3 categorias de filtro e os 3 projetos por conteúdo de front-end; adicionar um selo (.project-card__badge) distinguindo "Projeto real" de "Projeto de exemplo"; resolver os 2 links mortos restantes com um estado desabilitado explícito em vez de href="#" silencioso.

Resultado produzido

Categorias viraram front-end/javascript/css. O primeiro card agora é real: "Este portfólio", com link de verdade para github.com/RayaraChambela/portfolio-pessoal. Os outros dois ("Painel de agendamento", "Painel de tarefas") são exemplos fictícios rotulados como tal, com link aria-disabled="true" e texto "Em breve" — não é mais um <a> que finge ser clicável.

Evidência

Testado ao vivo: os 3 botões de filtro (Todos/Front-end/JavaScript/CSS) filtram corretamente os 3 cards por data-tags (confirmado via inspeção de DOM, visible: true/false mudando junto com o filtro clicado). O link real do GitHub abre a URL verdadeira; os 2 links "Em breve" não navegam para lugar nenhum (pointer-events: none via CSS), então não há mais clique silencioso sem feedback.

Análise do resultado

Esta foi, junto com o formulário (ver Contato), a correção de maior impacto no "veredito de especificidade" do critique: a seção deixou de contradizer a própria proposta do site. O selo "Projeto de exemplo" é uma escolha deliberada de honestidade sobre estética — poderia ter sido omitido para parecer mais "completo", mas isso violaria o Princípio de Produto #2 (honestidade acima de hype) registrado no PRODUCT.md.

Decisão

✓ Mantido: inclui a decisão consciente de manter 2 dos 3 projetos como "exemplo" em vez de inventar entregas falsas para parecer mais robusto.
